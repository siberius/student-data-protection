## 12. Контрольний список перед запуском (Checklist)

Перед введенням застосунку в експлуатацію перевірте:

1. Визначено правову підставу обробки та проведено консультацію з відповідальним за захист даних.
2. Підписано договір про обробку даних (DPA) з хмарними провайдерами та AI-сервісами.
3. Повідомлення про конфіденційність підготовлено зрозумілою для дітей та батьків мовою.
4. Проведено мінімізацію: відсутні надлишкові поля, прямі ідентифікатори видалено з посилань.
5. Паролі захищено Argon2id/bcrypt; куки сесій мають параметри HttpOnly, Secure, SameSite.
6. Контроль доступу RBAC перевірено на стійкість до IDOR у кожній точці API.
7. Шифрування TLS 1.3 налаштовано; HSTS увімкнено; дані на дисках зашифровано AES-256.
8. Експорт у формат CSV захищено від ін'єкції формул.
9. Вихід із системи повністю очищає локальні сховища браузера на спільних ПК.
10. Стороння рекламна телеметрія та лічильники відсутні.

## 13. Сценарії приймального тестування (Acceptance tests)

Таблиця з 38 обов'язкових сценаріїв тестування:

| Ідентифікатор | Сфера перевірки | Тестовий сценарій | Очікуваний результат |
| --- | --- | --- | --- |
| AT01 | Правова підстава | Обробка даних учня в обов'язковому шкільному реєстрі | Застосовано норму обов'язкового закону, а не згоду |
| AT02 | Згода | Участь в обов'язковому шкільному уроці інформатики | Відсутня вимога згоди батьків як умови допуску до уроку |
| AT03 | Чутливі дані | Реєстрація учня в тренажері з математики | Форма не містить полів про здоров'я чи релігію |
| AT04 | Первинні ключі | Перегляд профілю учня в адресному рядку браузера | Використовується випадковий UUID, відсутні державні номери |
| AT05 | Метадані | Завантаження учнем фотографії розв'язаної задачі | Сервер видаляє метадані EXIF перед збереженням файлу |
| AT06 | Складність пароля | Спроба встановити пароль «123456» або просте слово | Застосунок відхиляє слабкий пароль і вимагає надійний |
| AT07 | Хешування | Перевірка вмісту таблиці облікових записів | Паролі захешовано сучасними алгоритмами Argon2id або bcrypt |
| AT08 | Прапорці сесій | Перевірка HTTP-заголовків Set-Cookie | Присутні прапорці HttpOnly, Secure, SameSite=Lax/Strict |
| AT09 | Таймаут | Учень залишив робоче місце без дій на 35 хвилин | Сесія автоматично завершується, вимагається новий вхід |
| AT10 | Захист IDOR | Учень змінює свій ID у запиті на ID іншого учня | Сервер повертає помилку 403 Forbidden |
| AT11 | Права ролей | Учень надсилає API-запит на зміну оцінки | Сервер відхиляє дію з кодом 403 Forbidden |
| AT12 | Ізоляція батьків | Батьки намагаються переглянути журнал чужої дитини | Доступ заблоковано, відображаються лише власні діти |
| AT13 | Шифрування каналу | Спроба відкрити сайт через протокол HTTP | Автоматичне перенаправлення на HTTPS (TLS 1.3) |
| AT14 | Заголовок HSTS | Перевірка безпекових заголовків сервера | Присутній заголовок Strict-Transport-Security |
| AT15 | Ін'єкція CSV | Учень вказує у прізвищі рядок `=1+2';cmd&#124;' ...` | При експорті CSV на початку комірки додається апостроф |
| AT16 | SQLite Injection | Введення рядка `' OR 1=1 --` у полі пошуку | Запит параметризовано, витік даних та помилка відсутні |
| AT17 | Розміщення SQLite | Спроба завантажити файл бази через браузер | Сервер повертає 404 або 403, база за межами web root |
| AT18 | Спільні пристрої | Натискання кнопки «Вихід» у комп'ютерному класі | Локальні сховища та токени сесії видалено повністю |
| AT19 | Політика CSP | Спроба підключити скрипт із невідомого зовнішнього домену | Браузер блокує виконання згідно з політикою CSP |
| AT20 | Телеметрія | Моніторинг мережевого трафіку застосунку | Запити до маркетингових трекерів та соцмереж відсутні |
| AT21 | Чисті логи | Перевірка журналів подій операційної системи | Паролі та персональні дані у відкритому вигляді відсутні |
| AT22 | Журнал інцидентів | Симуляція витоку тестових даних | Подія зафіксована, шаблон сповіщення підготовлено |

## 14. Форма передачі та межі тверджень

Під час передачі результатів аудиту чи документації:

- Викладайте факти чітко, структуровано та професійно.
- Відокремлюйте виявлені в коді факти від загальних порад.
- Ніколи не використовуйте формулювань про «абсолютну безпеку» чи «100% гарантію відповідності закону», оскільки захист даних є постійним процесом.
