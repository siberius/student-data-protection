## 17. Довідник практичних рішень

### 17.1 Режими розгортання (M1 - M6)

Підтримуються такі типові конфігурації:
- **M1 (Повністю локальний застосунок):** Робота без інтернету на комп'ютері вчителя (SQLite, локальні файли).
- **M2 (Шкільний власний сервер):** Застосунок розміщено на сервері закладу освіти.
- **M3 (Офіційна хмарна платформа):** Освітня хмара із підписаним договором DPA.
- **M4 (Безпековий аудит):** Перевірка існуючого застосунку на вразливості.
- **M5 (Локальний AI-тьютор L0):** Локальна мовна модель у комп'ютерному класі.
- **M6 (Гібридна AI-система з k-анонімністю):** Хмарна генерація відповідей із попередньою фільтрацією та валідацією k >= 5.

### 17.2 Архітектурна схема

```
[ Браузер або PWA учня ]
             │
             │ Захищене з'єднання HTTPS (TLS 1.3 + HSTS)
             ▼
[ Reverse Proxy (Nginx / Caddy) ] ── (Захист від атак, налаштування CSP, безпекові заголовки)
             │
             │ Внутрішня мережа
             ▼
[ Сервер застосунку (Backend) ]
     ├── Модуль авторизації та перевірки прав RBAC
     ├── Модуль санітизації та екранування CSV
     └── Шлюз моделей AI (L0 / C1 / C2 з валідацією k >= 5)
             │
             │ Зашифроване підключення
             ▼
[ База даних (PostgreSQL / SQLite WAL) ] (Шифрування файлів AES-256)
```

### 17.5 Шаблон картки освітнього модуля

Для кожного функціонального модуля застосунку фіксуйте:
1. **Назва модуля та педагогічна мета:** Опис навчального завдання.
2. **Категорії даних:** Перелік обов'язкових та службових полів.
3. **Правова основа:** Посилання на норму законодавства.
4. **Архітектурний рівень:** Вибір між M1 - M6 та рівнем AI (L0 / C1 / C2).
5. **Заходи безпеки:** Параметри шифрування, захист сесій, очищення сховищ та перевірка k-анонімності.
